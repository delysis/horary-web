# Privacy and network behavior

The conversation, charts, place lookup, microphone audio and interpretation run locally. There is no analytics, hosted inference, remote dictation, remote font, feedback upload or automatic synchronization.

The first message prepares the pinned Gemma 4 12B IT QAT model and matching projector. Missing files are downloaded through native Rust HTTPS from Hugging Face and its delivery infrastructure. Hugging Face receives ordinary download requests and network metadata, never the question, chart or recording. The chosen artifacts are public and require no account or token. Setup respects the shared Hugging Face cache and verifies complete SHA-256 digests. Stop can pause an acquisition for later resumption.

The cache location follows HF_HUB_CACHE, HUGGINGFACE_HUB_CACHE, HF_HOME, XDG_CACHE_HOME, then ~/.cache/huggingface/hub. Horary shares blob locks and resumable .incomplete files, publishes verified blobs and snapshot links, and leaves refs/main untouched. Removing cached weights requires setup again. No speculative helper is currently used by the pinned native-kit API.

Microphone capture begins only when the user holds Space, Option–Space or the speech invitation and ends when the user finishes/cancels, the UI's two-minute timer expires, or the app exits. The native recorder additionally bounds memory. Audio remains in native memory behind a one-use receipt and is dropped after consumption or cancellation; it is never returned to the UI or saved in the conversation.

The default voice route tries macOS Speech with `requiresOnDeviceRecognition=true`, using installed language support and OS-controlled permission. It never permits Speech's network recognition route. Recognition and a first permission wait are bounded; unavailable local dictation falls back to Gemma hearing the audio directly. Native dictation saves its transcript; direct audio saves a labeled summary of the reader's understanding, not a claimed verbatim transcript. A developer-only comparison route retains Gemma transcription. macOS spoken replies use an installed system voice; text is passed as a process argument to the local speech utility, without a shell. No cloud voice is selected.

Prompt reuse is confined to the resident native worker's memory. The bounded saved-prefix bank contains fixed teaching messages, not private changing question inputs or audio. Imports require exact prefix agreement and live owner authority. A cancelled or failed inference does not authorize reuse of its private suffix. Nothing is written to a persistent prompt cache.

Conversation text, question, resolved place, chart, scroll revisions, worksheets and tool receipts are atomically saved as `conversation.json` in native app data. Whole readings are archived under `readings/` before replacement. Exact task input, original output and validation are also kept in private `method-receipts/` files for diagnosis. These may contain sensitive personal details. The application does not upload or encrypt these files. Legacy charts and review notes remain in their original local stores and are not deleted by the redesign.

The browser URL is a visual preview. It does not record through browser speech recognition or send a question to an AI server. The native app is required for the conversation. Legacy browser inference/export modules remain in the repository but are not entry points in the new interface.

When the first question is sent, Horary requests native device location with a bounded wait. The OS controls permission. Coordinates and device clock context stay in local reading state; no network geocoding is used. A coarse or conflicting fix is not substituted for the person’s stated place. The separate progress journal omits questions, audio and coordinates, retains timing and build identity, and rotates at approximately four MB.
