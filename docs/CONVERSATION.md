# Conversation and the unfolding reading

The September 14 direction replaces the chart-entry workspace with a conversation. Speak or type; the native agent resolves the place, casts the chart, and develops a provisional reading on a scroll. There is no branding, button, settings control or chart form. The system controls light/dark appearance. Questions, charts and testimony appear inline in one document. The browser is a visual preview of this native experience, not a hosted AI service.

The microphone is explicit: hold the speech invitation or Space anywhere outside editable text to begin, and release to finish. Option–Space also works while writing; ordinary spaces remain ordinary spaces. Escape and window blur cancel capture. Native CPAL capture produces mono 16 kHz WAV in memory. The default route uses installed macOS dictation with on-device recognition required. If unavailable, Gemma 4 12B IT QAT hears the audio directly through the matching projector and makes the first tool decision, without a separate transcription. Its understanding is visibly labeled as a summary. Corrections are ordinary conversation. The UI stops recording after two minutes; the recorder also enforces its own bounded storage. Audio is never returned through UI IPC or written into the conversation file. macOS can speak the reply using its installed system voice through `/usr/bin/say`; there is no shell or remote speech service. Other platforms currently use direct audio and retain text replies.

The first message prepares the local reader. Model acquisition still uses pinned, verified Hugging Face blobs and shared snapshot links. Downloading may require about 7.15 GB once. Escape pauses acquisition or cancels inference. A failed operation leaves the question and completed scroll sections saved.

## Authority

`src-tauri/src/conversation.rs` owns the conversation, tool loop, local file and chart revisions. Available actions are speak, find a place, cast a chart, write a scroll section, restore a reading, or start a new question. Text decisions are schema-constrained at sampling time. Direct audio's first action is parsed into the same bounded Rust action type, then validated by the same native tools; malformed understanding pauses without running a tool. The controlled API does not admit media, and the worker explicitly rejects that combination. It cannot provide a filename, execute a command, supply arbitrary coordinates, or substitute model-produced planetary positions. Place IDs must come from the offline geocoder or validated native device coordinates. The first question requests device location and clock context; a stated place overrides that default. A time zone alone never supplies coordinates. Civil times are resolved against that place's IANA timezone, including DST gaps and repeated times.

`crates/horary-ai-core/src/astronomy.rs` ports the inherited approximate seven-planet ephemeris and Regiomontanus houses into safe Rust. The port has parity fixtures at three dates/locations; parity is not a new certification of astronomical accuracy. It feeds the previously corrected dignity, reception, solar-condition and hourly event rules. The UI only renders the returned chart.

Every chart revision clears the current interpretation and retains its predecessor. Every executed tool has a receipt. Three ordered method stages cite current calculated evidence and relevant editorial book-rule IDs. Rust derives the planets from role-house choices. Directed receptions are separate from own dignity. Judgments must cite the calculation boundary; changing a premise clears its dependent conclusions. Each margin distinguishes fact, source and inference. Ask “why?” to explore evidence, or ask to return to a previous reading. The agent has a restore tool that preserves the version being left. Evidence-ID validation prevents dangling references, but does not prove that the model's prose accurately interprets its reference.

The conversation is atomically persisted in the native app-data `conversation.json`, with a 16 MB bound. No old chart records or review notes are deleted. There is currently one active conversation; a separate conversation library and export-by-conversation are still to be completed. The older review export backend remains available to legacy callers.

## Book fidelity

The agent receives the curated editorial rule catalog from `reading_method.rs`, with printed-page references. Longer method notes in `conversation_method.txt` remain review background; repeating the entire document in each model prompt is unnecessary. These preserve the important lost-object exception: the Moon can signify the lost object applying to Lord 1 for recovery. Inanimate lost possessions require comparing Lords 2 and 4. The agent must establish roles, avoid automatic damage/theft assumptions, and distinguish astronomical aspect times from symbolic timing of the earthly matter.

The book OCR remains private and is not bundled. The method notes are inspectable software policy, not Eileen's final endorsement. Model testimony remains provisional. In particular, approximate ephemerides and hourly seven-day event brackets do not certify fine event order or every traditional doctrine.

## Voice and cache comparisons

No voice settings control is added to the document. Developers can launch with `HORARY_VOICE_MODE=auto` (default), `native`, `direct` or `gemma-transcription`. Explicit native mode reports unavailable dictation instead of falling back, so comparison receipts cannot silently measure another route. Auto never falls back to Gemma transcription. Native dictation requires OS permission and installed on-device language support; neither is assumed. Its authorization and recognition waits each have a six-second bound. Audio and any waiting receipt are discarded on cancellation.

Fixed method instructions precede changing state. During a turn, native chart facts enter the prompt once, with further facts and tool receipts appended as they become available. Completed section prose is not fed back into the prompt. Changing chart revision retires earlier chart context. Native-kit reuses only an exact token prefix bound to its resident sequence; it trims a divergent suffix and replays the final prompt token for fresh logits. Failure and cancellation invalidate cache authority. Media processing and multi-request/CFG paths have no reuse claim. Logical admission and context limits still charge the full prompt; cache hits reduce physical decoding only. Reopening the app starts cold.

Real local runs still contradicted correct receptions and overreached on a one-year marriage question. The main document therefore presents Rust-owned method prose and calculated testimony, with the reader’s original draft and rationale retained in “How this follows.” It does not publish that draft as an answer. Three successful stages finish with an explicit open outcome. Schema field order is preserved: roles and evidence precede prose, with a regression against accidental alphabetization. This is a working method for assessment, not a qualified autonomous horary verdict.
