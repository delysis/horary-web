# Conversation and the unfolding reading

Speak with one unbranded document. Questions, the chart and short interpretations unfold inline. Appearance follows the system. Voice is the ordinary input. A quiet text entry appears only when the microphone is unavailable; there is no chart form or settings screen. Earlier words remain readable; corrections are spoken in conversation and their originals remain in the record. Interface chrome uses icons or single-word labels; operating instructions belong in tooltips and accessible descriptions.

Each app launch opens a fresh reading and archives the previous leaf. Renderer reloads retain the current leaf. The upper-right page icon opens a modal history pane with saved readings, a plus icon for a new reading, earlier versions and developer receipts. Command–N and the native File menu also start another reading. The pane traps keyboard focus, closes with Escape or an outside click, and returns focus to its opener. While a reply is in progress, history remains viewable but replacement is blocked. Native commands carry the reading identity, so a delayed input cannot enter a different leaf. The full conversation, chart, revisions, worksheets and diagnostics are archived before replacement.

## The method

[The living process map](LLM_PROCESS.md) is the primary review document. It contains Mermaid diagrams, exact stage lessons, output contracts, source quotations with printed-page references, and authored examples captured from the actual Rust scheduler. A freshness test detects source drift. The complete private OCR is not bundled.

`horary_conversation.rs` makes the model the conversational reader. Recognition extracts proposals; Rust holds the canonical clipboard and computes missing facts and method boundaries. The separate cached conversation lesson receives recent dialogue, accepted observations, missing-input reminders, native anchor and specialist findings. It phrases its own reply and can select the reminder it wants to pursue. Only the native reducer can change facts, and only the readiness constructor can authorize a reading. Catalogue questions are private examples, never user-facing scripts.

`horary_pipeline.rs` owns the sequence. Intake preserves the actual question and horizon before casting. Native place and moment checks run independently: usable device coordinates and the receipt instant are defaults; a stated chart place or historical understood moment overrides them. Event context is not automatically a chart override. Civil-time parsing waits for the chosen place's time zone and native clock. Rust handles DST gaps and overlaps.

The conversational clipboard exposes `chart_context` and `event_context` separately. The former is the verified reader anchor; the latter retains sourced event place/time observations, including missing or disputed states. Device coordinates do not establish Bob's market location. The reader can inquire about a venue when it matters to the question; a named venue is not mandatory for every reading. Recognition sees the reader's preceding question as well as the person's reply, so contextual answers can be extracted without making every conversational inquiry a chart prerequisite. Using the device as the automated reader's ordinary location is an application convention grounded in Frawley's astrologer-place rule (printed pp. 7–8).

Rust calculates the chart, binds people/objects to named role options, counts turned houses and derives their rulers. The role lesson selects the relevant supplied option IDs and explains the choice. Required context and role slots must be filled before testimony can run. Condition, directed reception and contact mechanics then run in one native batch; lost matters add location as the fourth task. Each receives its own lesson and facts. The final judgment combines accepted data and answers the original question. Ask why to inspect one step; place/moment explanations receive the actual chart even before an interpretation exists.

Model output is a proposal. All single and batch results use one acceptance path for bounded fields, source-backed extraction, required role slots, current evidence IDs, directed reception references, contact sign-change status and calculation boundaries. Rejection retains the output and retries that same stage with its unchanged original input. A necessary user question suspends it; replies return to that stage. Completion requires accepted data, not an existing chart or merely valid JSON. Cancellation/backend failure pauses unfinished work. These checks do not certify all prose or astrology; Eileen should review the evidence, source method and interpretation together.

The inherited approximate seven-planet ephemeris, Regiomontanus houses, corrected dignity/reception rules and hourly seven-day contact search remain calculation boundaries. Exact symbolic timing is bypassed because native travel to moving-target perfection is not available. A seven-day absence does not settle a one-year question.

## Permissions, voice, acquisition and caching

Startup requests microphone, speech recognition and location consent in one sequence, before listening. macOS owns separate consent dialogs, so they cannot be combined into one grant. The native request sequence is process-local and repeats on every launch; no refusal preference is written into settings. A denied or absent microphone reveals text entry and a microphone-access icon. Denied speech recognition disables local wake recognition but leaves direct Gemma audio available; denied location is handled conversationally. Returning from System Settings refreshes authorization without losing the reading. macOS may require relaunch after changing microphone consent.

References: [Apple capture authorization](https://developer.apple.com/documentation/avfoundation/requesting-authorization-to-capture-and-save-media), [Apple microphone recovery](https://support.apple.com/en-us/102071), [Apple location authorization](https://developer.apple.com/documentation/corelocation/cllocationmanager/requestwheninuseauthorization()).

On macOS the document speaks its opening and replies, then offers a twenty-second reply window. Outside that window, a whole “Oracle” wake word addresses a new turn. Speech recognition is strictly on-device. A 1.4-second pause in both sound and transcript updates ends the utterance; only a final recognition result becomes a one-use receipt. Partial and ambient hypotheses never enter model prompts, logs or saved readings. Tasks renew every 45 seconds, and both audio and callback queues are bounded. Wake listening pauses while the document speaks, while inference runs, in history, and when the window loses focus. Escape pauses it until deliberate interaction. Generation leases reject delayed wake events. The native owner releases the microphone before it publishes a question.

The luminous “?” remains a fallback: one press starts microphone capture, another finishes. Its glow represents acknowledged listening; a moving ring marks opening or processing. A second press during microphone startup cancels that start, rather than submitting an accidental clip. While working, it pauses the reply. Tooltips explain the mark without visible instructions. Space/Option–Space are not global speech shortcuts; native button keyboard activation still works when it has focus. Escape, window blur and opening history cancel unfinished capture. Closing history with Escape does not pause ongoing inference. Manual capture produces bounded mono 16 kHz WAV in memory. Audio never crosses UI IPC or enters saved conversations.

Wake turns use native streaming dictation. The manual route tries installed, strictly on-device macOS dictation; if unavailable, Gemma hears the audio directly and supplies intake's meaning summary and worksheet in one call. Gemma transcription remains a developer comparison route. `HORARY_VOICE_MODE=auto|native|direct|gemma-transcription` selects the manual route without adding a settings screen. Explicit native mode does not silently fall back. Direct and Gemma-transcription comparison modes use the microphone mark, without wake listening. Other platforms currently use that manual capture path; native spoken replies and wake recognition are macOS-only. macOS replies use its installed voice, with completion acknowledged before listening resumes. Speech permission or missing local language assets can disable wake recognition; the microphone mark remains usable.

First use acquires pinned verified weights and projector automatically in the shared Hugging Face cache. No Python, Hugging Face CLI, duplicate weight store or hosted inference is required. Escape pauses acquisition or inference; saved words and completed passages remain.

One native-kit owner holds one weight copy. It admits up to four independent generation cases. Fixed lessons have separate authenticated saved prefixes, held in memory within one eighth of physical RAM, capped at 4 GiB. Single text tasks use constrained JSON; independent tasks use ordinary cached batching and native validation because the current constrained API lacks per-case supplied prefixes. Audio does not claim prefix reuse. Eviction, shutdown or changed teaching can require prefill again. See [format experiments](FORMAT_EXPERIMENTS.md) and [verification](VERIFICATION.md).

## Review records

“Evidence” reveals each passage's checks, calculated evidence and book extracts. Detailed input, original model output, validated worksheet, token counts, first-token delay and tool receipts are further inside **History → Receipts → Processing**. Technical processing is kept out of the ordinary document.

`conversation.json` and reading archives use bounded atomic writes. A separate rotating `reading-progress.jsonl` journal logs build identity and metrics without question text, coordinates or audio. Private method receipts retain exact task input and output for diagnosis. They remain local; no automatic sharing occurs. Microphone interaction, ambiguity, interruption and expert assessment still require native review.
